\section{Results}

\subsection{Evaluation Data and the Completeness Filter}

We evaluate on the MNIST test set \cite{lecun1998}, 10,000 handwritten digit
images rendered at 100$\times$100 pixels. The completeness filter is a per-image
annotation made by hand before any classification run and recorded in
\texttt{mnist\_all\_manifest.csv} in the public repository: an image is marked
complete when its stroke has no break and incomplete otherwise. The annotator
saw three panels per image, the grey-scale original, the binary mask at
$\theta = 110$ and the one-pixel skeleton, and marked the image complete when
the digit is fully drawn with all strokes connected. The annotation
uses only that structural property, not the class label and not the
classifier's output. Each image carries one label, and inter-rater agreement
was not measured. Other revisions of the manifest list 8,704 and 8,708
complete images, so the labels of a few images are unstable. The system does
not detect completeness itself. The repository holds a heuristic detector built
on connected components, erosion and skeleton endpoints; its agreement with the
manual labels was not measured, and the evaluation does not use it. A broken stroke
violates the assumption the graph representation of Section~III rests on, and
the graph built from such an image describes a different figure. Recognising
broken structures needs a separate mechanism, associative recognition, which
the system does not implement.

The filter admits 8,707 of the 10,000 test images and excludes 1,293, or
12.9\%. The accuracy reported first is therefore conditional on the filter
and does not transfer to full MNIST; Section IV-B adds the figures over the
full test set. The filter also acts unevenly across
classes (Table~\ref{tab:perclass}). Class~1 keeps 1,129 of its 1,135 test
images (99.5\%), while class~8 keeps 582 of 974 (59.8\%). Per-class figures
therefore rest on samples of very different size, and class~8 has the narrowest
basis.

A further 22 admitted images (0.25\%) failed graph construction:
skeletonization produced no connected graph at any threshold of the retry
ladder (Section III-B). We count these as pipeline
errors. A classification decision was produced for 8,685 images.

\subsection{Classification Results}

91.92\% precision, 91.13\% recall and 91.34\% F1. The three averaged
figures are weighted by class support; the unweighted macro averages over the
ten classes are 92.22\%, 91.22\% and 91.54\%.

Per-class figures spread much wider than the totals
(Table~\ref{tab:perclass}). Precision is highest for class~0 (99.87\%) and
class~8 (98.74\%), whose concepts attract almost nothing from other classes.
Precision is lowest for class~7 (82.01\%) and class~6 (84.88\%), which take
on images belonging to neighbouring classes. Recall orders the classes
differently, with class~2 (77.59\%) and class~4 (84.00\%) at the bottom.

The system made 770 wrong decisions: 726 assigned the image to a wrong class,
and in 44 no concept activated and the image was left unrecognised, mostly in
class~6 (16) and class~8 (14).

Counted against all 10,000 test images, three mechanisms reject an image: the
filter (1,293 images, 12.93\%), failed graph construction (22, 0.22\%) and no
activated concept (44, 0.44\%). Only the last two are automatic. The reject
rate is 13.59\% and the coverage 86.41\%: 8,641 images receive a class. The
selective risk, the error rate among those 8,641, is 8.40\% (726 errors). With
every rejected image counted as an error, accuracy over the full test set is
79.15\% (7,915 of 10,000). Coverage runs from 58.2\% for class~8 to 98.9\% for
class~1 (Table~\ref{tab:perclass}), and the error rate among the labelled
images of a class from 3.2\% for class~8 to 22.0\% for class~2.

A separate run submitted all 10,000 test images with no filter, using the same
13 concept attractors and the same parameters. Graph construction failed for 58
images, 54 activated no concept and 1,667 received a wrong class, so 8,221 are
correct: 82.21\% of the full test set. On the 9,942 classified images accuracy
is 82.69\%, precision 84.57\%, recall 82.69\% and F1 82.83\%. The last column
of Table~\ref{tab:perclass} gives the per-class recall of this run over all test
images; class~8 falls to 62.11\%. The manifest revision of this run lists 1,295
incomplete images, and the run is correct for 310 of them, or 23.94\%. The run used a later code revision, which softens the
out-of-range penalty of Section III-E for narrow intervals. On the images
annotated complete it scores 90.89\%, against 90.90\% for the baseline run
counted the same way.

\subsection{Decision Trace}

Every decision decomposes into values a reader can check. We show this on
image \cid{mnist\_test\_2\_00766}, true class 2, predicted 7. We chose a
misclassification: an explanation has to hold for a wrong decision as well
as for a correct one. Fig.~\ref{fig:trace} shows the construction of the graph and the two
competing concepts; Table~\ref{tab:trace} gives the decision trace.

The image graph has complexity 21. The complexity pre-filter runs first. The
richer concept of digit~2, \cid{2\_2}, has 12 nodes and complexity 24, so the
condition $24 > 21$ removes it before any comparison. The impoverished input is
visible in the image: binarization lost the lower loop of the 2, the closed
structure became an open spur, and the graph holds neither a cycle nor an
intersection point.

Two concepts then compete. Concept \cid{7\_1} has five nodes, every one of them
substituted within the learned intervals of the concept, at substitution costs
between 0.04 and 0.39, and reaches similarity 0.8317. Concept \cid{2\_1} has
seven nodes and matches the input structurally, but three of its nodes each
carry one feature outside its interval, and each takes the full 1.0 penalty:
the StartPoint on \texttt{distance\_to\_centroid} (0.56 against $[0.69, 1.00]$),
a CornerPoint on \texttt{normalized\_x} (0.20 against $[-0.70, 0.10]$) and a
horizontal Vector node on \texttt{length\_ratio\_to\_max} (0.31 against
$[0.43, 1.00]$). With their in-range features added, the three node
substitution costs are 1.01, 1.10 and 1.30. Its similarity is 0.7300.

Complexity is $\kappa = 9$ for \cid{7\_1} and $\kappa = 13$ for \cid{2\_1}, so
the prior of \eqref{eq:score} favours \cid{2\_1} by 0.053 and does not close
the gap. Winner-take-all on the score picks \cid{7\_1}: 1.149 against 1.100.

The mechanism holds beyond this one image. Across all 111 2$\rightarrow$7
errors, \cid{2\_1} entered the comparison every time and lost on similarity

digit~2 win on similarity and then lose after the complexity prior was applied.

\subsection{Sensitivity and Ablations}

No single-factor ablation was run on the baseline configuration; the results
below come from other runs.

Three back-to-back retrains on later revisions of the code and of the
training corpus (869 images from 85 samples) each consumed the samples in a
different order. All
three reproduced the node count of every concept attractor in the baseline
alphabet. Accuracy on the classified images was 90.68\%, 89.93\% and 90.93\%.
In an offline study, ten shuffled orders gave \cid{7\_1} and \cid{8\_1} the
same labelled topology every time; \cid{2\_2} kept 12 nodes, and 64\% of its
order pairs had identical topology. We did not form concepts from a random draw
of the training split, did not vary the number of concept attractors, and did
not vary augmentation. The effect of those three choices on accuracy is
unknown.

The previous configuration scored 85.80\% under the same protocol. It used
the cost ladder 0, 0.65, 0.75, 1.0, 1.5, 10, $\varepsilon_w = 1.0$, 14 features
and a 15\,s GED deadline, and it preceded one change to skeletonization and the
re-formation of five concept attractors. The gain of 5.33 points cannot be
split among these six changes. The later code revision of Section IV-B softens the out-of-range penalty and
leaves accuracy on complete images within 0.02 points, though it carries other
code changes as well. On an earlier configuration and a 3,000-image sample,
removing the complexity prior of \eqref{eq:score} lowered accuracy by about 3
points, to 72.00\%. For the 111 2$\rightarrow$7 errors, lifting the complexity
pre-filter changed no decision (Section V). We did not run the evaluation set
without the pre-filter and did not test a soft pre-filter.

\subsection{Inference Cost}

An image is compared against at most 13 concepts, each comparison under a
5\,s deadline, so the theoretical upper bound is 65\,s per image. The measured
times stay far below it.

We measured end-to-end time over the whole evaluation set on one Apple M1 Pro
workstation (10 cores, 32\,GB) running the pipeline in 26 Docker containers: a
connector, four skeletonization, four contour analysis and sixteen
classification instances, and the concept creator. The clock runs from the
first HTTP submission to the last result and includes database writes and
message-queue hops. The three runs of Section IV-D took 1,279\,s, 1,431\,s and
2,018\,s for 8,704 to 8,708 images, which is 147, 164 and 232\,ms per image.
These are throughput figures with the stages running in parallel; the latency
of a single image was not recorded. Each run was slower than the one before.
Every run leaves its test graphs in the database, which held 514k nodes after
the third; that growth is the likely cause, but we did not isolate it. Forming
the 13 concept attractors took 528\,s, 746\,s and 966\,s.

Per-stage times exist only for the 770 misclassified images of the baseline
run, because a run stores profiling records only for those. Their medians are
52.8\,ms for skeletonization (maximum 533\,ms), 211.5\,ms for contour analysis
(maximum 1,905\,ms) and 167.1\,ms for the classification stage, meaning all GED
comparisons for one image together (99th percentile about 0.84\,s, maximum
1,414\,ms). No profiled image came close to the 5\,s deadline of a single
comparison, so on those images the solver finished its search and the reported
distances are completed results. The subset holds no correctly classified
image, so these medians are not a typical-case estimate.

Three quantities were not measured: the time of an individual GED comparison,
memory use, and the growth of inference time with the number of concept
attractors. The number of comparisons per image is at most the number of
concept attractors that pass the pre-filter.

\section{Discussion}

The explanation here is the decision object itself. No second model
approximates the classifier from outside. To see why an image received a class,
a reader opens the image graph and reads the learned intervals of the winning
concept attractor and the cost charged for each feature. The trace in
Section~IV-C runs the whole chain, from the complexity pre-filter down to one
out-of-range value, \texttt{normalized\_x} at 0.20 against the interval
$[-0.70, 0.10]$. Post-hoc attribution methods build
their explanation after the fact by perturbing the input
\cite{ribeiro2016,lundberg2017}, and that construction can be manipulated
\cite{slack2020}. Decisions with consequences are better taken by models
interpretable by construction \cite{rudin2019}.

The same property applies to the failures. Binarization loses the lower loop of
the digit, so the image graph carries no intersection point, and the pre-filter
removes \cid{2\_2} in 86 of the 111 2$\rightarrow$7 cases. The pre-filter is
not the cause: in a control run with it lifted, \cid{2\_2} won none of the 111,
because an intersection-point condition blocks its match to a graph without an
intersection. The error has two causes: the lower loop lost at binarization,
and the full interval penalties on \cid{2\_1} against the in-interval match of
the five-node \cid{7\_1}. The error can be named and its prevalence checked
over all 111 cases.

Traceability defines the application niche: tasks where the answer has to be
auditable. Verification of handwritten marks in document workflows, inspection
of industrial marking, and tutoring systems that must show a learner the reason
for a grade share the property that a human resolves every disputed decision. A
decision record of the named concept, its node substitutions and its
per-feature costs goes into that review without a separate explanation module.
For a dependability audience the property on offer is auditability: every
decision leaves a record that a person can check against the input without
re-running the system.
The small training set also lowers the cost of starting on a new set of marks:
one concept attractor forms from 3--9 samples and their augmented variants
(Section III-D). An earlier
prototype reported 82.44\% on six classes \cite{parzhyn2025energy}; the two
numbers are not comparable, since the class set, the test set size and the
formation procedure all differ.

Several limitations bound the result. The headline metric is conditional on the
completeness filter, a manual annotation with one label per image and no
measured inter-rater agreement, which excludes 12.9\% of the test set unevenly
across classes. The training samples were chosen on the same completeness
criterion as the test filter, so the evaluation measures the system inside the
regime it was built for, and the exclusion does the most work in the classes
with the lowest admission rates (8, 9 and 6). The 76 training samples were
selected by hand. A different sample order moved accuracy by about one point
(Section IV-D), but random selection, the number of concept attractors and
augmentation were not varied, so part of the accuracy may come from a fortunate
choice. We ran no non-neural structural baseline: no classifier on contour or
skeleton descriptors, no template matcher, and no nearest-neighbour GED against
the unreduced training graphs. The last one would show what the reduction to 13
concept attractors contributes. The paper therefore supports no claim that
concept attractors outperform other structural methods. No single-factor
ablation of the edit costs, the feature weights, the complexity prior or the
pre-filter was run on the baseline configuration. Inference time is measured
end to end, but per-stage records cover only misclassified images, and
per-comparison time, memory use and scaling with the number of concept
attractors were not measured. The evaluation covers MNIST only. We evaluated no
second dataset and none of the application tasks named above, so the paper
does not establish generalization beyond handwritten digits or dependability in
those workflows. Tolerance to rotation
is limited to the small range covered by augmentation. The contour representation
discards texture and gradients, which confines the method to silhouette and
stroke images. Broken contours need associative
recognition, which the system does not have.

\section{Conclusion}

We formed an alphabet of 13 concept attractors for ten digit classes by
structural reduction of 76 hand-selected training samples and their augmented
variants, with no backpropagation anywhere in the procedure. Classification by graph edit
distance with interval-based feature weighting recognises 8,685
complete-contour MNIST images at 91.13\% accuracy, 91.92\% precision,
91.13\% recall and 91.34\% F1. The evaluation is stated with its filter:
12.9\% of the test set is excluded. Counted over all 10,000 test images the
system assigns a class to 86.41\% at a selective risk of 8.40\%, and without the
filter it classifies 82.21\% correctly. Each decision decomposes into a named concept, a list of
node substitutions and a per-feature cost, and the dominant 2$\rightarrow$7
error was traced through that decomposition over all 111 cases. End-to-end
inference took 147 to 232\,ms per image, and on the profiled images the 5\,s
deadline of a single comparison was not reached. Work ahead covers associative
recognition for broken contours, a nearest-neighbour GED baseline on the
unreduced training graphs, single-factor ablations of the matching costs, and
formation from randomly drawn training samples. The source code and the run
artefacts are public at \url{https://github.com/NaturalAGI-Lab/NaturalAGI}.
